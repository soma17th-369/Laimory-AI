# reference-ignored-files

현재 worktree에 빠진 로컬 전용 자원은 주 워크트리의 같은 상대 경로를 원본으로 삼아 직접 사용한다. 파일을 복사해 서로 다른 사본을 만들지 않는다.

## 원본 경로 찾기

1. 사용자가 지정했거나 실행 오류에서 확인된 경로만 처리한다. `.gitignore`의 모든 항목을 열거하거나 탐색하지 않는다.
2. 현재 worktree에 대상이 있으면 그 경로를 그대로 사용하고 끝낸다.
3. 대상은 저장소 루트 기준 상대 경로로 정규화한다. 저장소 밖을 가리키는 경로는 이 스킬로 해석하지 않는다.
4. `git check-ignore -- <상대경로>`로 대상이 실제 ignore 규칙에 포함되는지 확인한다. 포함되지 않으면 일반적인 누락 파일 문제로 보고 이 스킬을 중단한다.
5. `git rev-parse --path-format=absolute --git-common-dir`의 결과에서 마지막 `.git`을 제외한 디렉터리를 주 워크트리 루트로 사용한다.
6. 주 워크트리 루트와 대상 상대 경로를 결합하고 존재 여부를 확인한다. 원본도 없으면 만들거나 다른 worktree의 값을 임의로 고르지 말고 누락 사실을 알린다.

경로를 계산할 때 문자열 연결 대신 현재 셸의 경로 결합 기능을 사용하고, 공백과 한글이 있는 절대경로를 항상 인자 하나로 전달한다.

## 참조하기

- 설정 파일은 도구의 `--env-file`, `--config` 같은 명시적 경로 옵션에 원본 절대경로를 전달한다.
- `.venv`는 주 워크트리의 Python 또는 실행 파일을 절대경로로 직접 호출한다.
- 내용을 읽어야 하면 원본 경로를 직접 읽되 기본적으로 읽기 전용으로 취급한다.
- 도구가 현재 경로의 고정 파일명만 지원하면 먼저 프로세스 환경 변수나 명시적 경로 옵션을 찾는다. 그것도 불가능하면 중단하고 사용자에게 알린다. 복사, 이동, 심볼릭 링크, 정션, 하드 링크를 자동으로 만들지 않는다.

## 안전 규칙

- `.env`, credential, token 등 비밀값의 본문을 로그·관측·응답에 출력하지 않는다. 경로와 존재 여부만 보고한다.
- 원본 수정은 여러 worktree에 영향을 줄 수 있다. 사용자가 해당 원본 변경을 명시적으로 요청하지 않았다면 수정하지 않는다.
- 원본을 사용한 명령이 파일을 갱신할 수 있는지 확인한다. 읽기 전용 사용이 보장되지 않으면 실행 전에 사용자 승인을 받는다.
- Git에서 ignored 파일의 내용을 복원할 수 있다고 가정하지 않는다. 이 스킬은 주 워크트리에 이미 존재하는 로컬 원본만 참조한다.

완료 시 어떤 상대 경로를 어느 주 워크트리 원본에서 참조했는지와 복사본을 만들지 않았음을 간단히 알린다. 비밀값은 요약에도 포함하지 않는다.
